# 系统架构

```
┌─────────────────────────────────────────────────────────────┐
│                      前端 (Vue/React)                        │

│                      Nginx (反向代理)                         │
├─────────────────────────────────────────────────────────────┤
│                    FastAPI 后端服务                           │
│  ┌──────────┬──────────┬──────────────┬──────────────────┐ │
│  │ 模块一   │ 模块二   │ 模块三       │ 模块四           │ │
│  │ 用户画像 │ 知识图谱 │ 个性化推荐   │ 阅读生态         │ │
│  └────┬─────┴────┬─────┴──────┬───────┴────────┬─────────┘ │
│       │          │            │                │           │
├───────┼──────────┼────────────┼────────────────┼───────────┤
```

## 数据存储职责

| 存储 | 用途 | 负责模块 |
|------|------|---------|
| **MySQL** | 用户、图书属性、阅读记录、评分、评论、书架 | 模块一、模块四 |
| **Neo4j** | 图书-作者-标签-出版社 实体关系图谱 | 模块二 |
| **Redis** | 用户会话缓存、热门推荐缓存、相似度矩阵缓存 | 模块三 |
| **ElasticSearch** | 图书全文搜索 | 模块二 |

## 关键设计决策

### 1. 双数据库架构 (MySQL + Neo4j)

- MySQL 存储实体属性（书名、作者名、用户信息）
- Neo4j 存储实体间关系（作者关系、标签关系、相似关系）
- 通过 `book_id` / `author_id` 等统一 ID 关联两个数据库

### 2. 分层架构

```
API 层 (endpoints/)  →  处理 HTTP 请求/响应
    ↓
服务层 (services/)    →  业务逻辑
    ↓
数据层 (models/)      →  ORM / 数据库操作
```

### 3. 推荐系统流程

```
用户登录
  │
  ├─→ 模块一: 构建用户画像 (tag偏好、作者偏好、高分图书)
  │
  ├─→ 模块二: 为高分图书查询图谱路径
  │     └─→ 返回候选图书 + 推理路径
  │
  └─→ 模块三: 混合推荐
        ├─ ItemCF 相似度推荐 (40%)
        ├─ 图谱推理推荐 (40%)
        ├─ 热门推荐 (10%)
        └─ 新书推荐 (10%)
              │
              └─→ 加权融合 → 生成推荐列表 + 推荐理由
```

## 技术选型理由

| 选择 | 理由 |
|------|------|
| FastAPI (非Flask) | 自动生成 Swagger 文档、异步支持、Pydantic 数据验证 |
| Neo4j (非其他图库) | Cypher 查询成熟、可视化生态好、社区活跃 |
| ItemCF (非UserCF) | 图书数量相对稳定，用户数量可能快速增长，ItemCF更适合 |
| 混合推荐 | 单一策略各有短板，加权融合兼顾精度与可解释性 |
